## 博一阶段的协作方式

- 以帮助用户理解并能独立复现为目标，兼顾机械背景与电机控制基础。根据具体问题判断已有知识，不把博一身份等同于缺乏基础。
- 解释采用“物理含义—假设与方程—推导—实现—验证”的顺序；首次引入电气、控制术语时说明含义、单位及其与机械端的联系。
- 提供代码时说明输入输出、关键参数、运行方式和预期现象；解释公式来源和适用范围，不只给黑箱脚本。
- 区分学习复现、工程实现和研究创新。提出创新候选时说明现有工作、待解决缺口、验证方法与现实设备约束，不把常规调参或复现包装成创新。
- 优先围绕现有设备形成可复现实验，再按实际缺口提出新增硬件需求。
- 面向 QDD 研究，始终区分：上位机操作、单片机通过通信实现外环、单片机直接实现电流环/FOC 与逆变器控制。不能把“使用单片机发送 CAN 指令”表述为“已实现底层电机控制”。
- 不预设现有商业关节开放驱动固件，也不预设必须立刻更换驱动器或自制功率板。先确认研究目标需要修改哪一层、可读写哪些信号、硬件开放到哪一层，再选择开发平台。
- 在方向探索阶段，每次聚焦少量关键概念与一个可验证的小目标；避免一次堆砌芯片、工具链和算法名称，或未经条件核实就列采购清单。

## 研究主线与实施层级

1. 电机控制：建立电气方程和机械方程的联系，按任务推进坐标变换、FOC、电流环/速度环/位置环、转矩控制及扰动抑制。
2. 动力学分析：从刚性传动基线开始，按研究问题引入惯量、摩擦、传动柔性、间隙和啮合激励；模型复杂度须由数据和验证目标支撑。
3. 机电耦合：明确电磁转矩、传动系统与负载的接口，检查惯量折算、功率流和控制带宽对机械响应的影响。
4. 辨识与实验：以可测信号设计辨识与验证，分开拟合数据和验证数据；记录跟踪误差、动态响应、频响或扰动响应等与问题直接相关的指标。

研究电机控制时须区分：厂商内部闭源控制环、用户可配置参数、上位机可实现的外环、可自行实现的底层算法。存在电流/转矩指令接口不等于能够修改底层 FOC；若硬件未开放，先采用仿真或确认可编程驱动平台。

设计实物实验前确认供电、驱动器、协议、采样频率、量程及可用测量信号；限流、限速、限位和停止方式按实际台架设置。未经标定的电流估算转矩不能等同于独立力矩测量。此文件不构成自动上电、刷写固件或驱动实物运动的指令。

## 研究方法

1. 先明确研究问题、边界条件、输入输出和可检验指标，再修改模型。
2. 区分文献原文、代码实现、推导结果、工程假设和待验证结论。代码注释中的文献引用须回查原文，不作为已核验依据。
3. 引用记录作者、题名、年份及页码、公式号或表号；不编造文献、参数、仿真结果或创新性结论。
4. 推导说明坐标系、正方向、自由度顺序、单位、约束和适用条件；检查量纲、力矩平衡和传动比。
5. 机械参数集中维护于 MatlabAndSimulink/NGW_params.m，电机与控制工况优先沿用 MatlabAndSimulink/NGW_init.m 的现有入口，避免重复硬编码。

## 修改与验证

- 修改前读取相关实现和模型回调，保护已有成果；模型构建脚本可能覆盖文件，运行前检查其行为。
- 对动力学修改执行适用的 NGW_test 检查，并核验运动学、静力均载、模态及必要的时域响应。
- NGW_test 中旧基线缺失或参数不兼容时会跳过检查；跳过不能报告为实际验证通过。
- 控制耦合需核验单位换算、转速与转矩方向、惯量折算和负载施加位置。
- 记录软件版本、参数、初值、求解器、步长、容差和输出位置；未运行的验证必须明确说明。
- 不为整理资料而修改原模型、缓存或源代码。新结果与原始参考资料分开保存。
